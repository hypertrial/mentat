# Cockpit evidence projection v1

Add optional `evidence.inspect` and `evidence.compareScoped` capabilities to the existing stdio v1 bridge. Existing methods and saved formats remain unchanged. Inputs must identify an existing validated project-verification record exactly, including canonical repository root, base, revision, runner, run ID and contract digest. A mismatched, foreign, stale, missing or damaged record is rejected. Inspection is historical and does not assert current approval or candidate freshness.

`evidence.inspect` takes `{repo,base,revision,runner,runId,contractDigest,state?}`. Its result is `{run,claims,environment,omissions}`. `run` contains `runId`, `base`, `revision`, `runner`, `contractDigest`, `manifestDigest`, `status` and optional `qualificationStatus`. Claims contain saved `id`, `statement`, flat `assumptions`, optional saved `locations`, structured `assurance` where recorded, and `checks`. Checks contain `id`, `method`, `status`, `artifacts` (role to `{name,sha256}`), `artifactOmissions` and `logOmissions`; formal checks include `engine` and qualification checks include available outcomes and case results. Locations are only recorded claim provenance citations; absence is never inferred. Environment contains only saved runner and available safe tool version identifiers. Omission labels state that local paths, commands, logs and unrecorded information are unavailable or withheld. Artifact names and hashes reference validated bundle entries; contents are not returned. Reject a response exceeding the bridge frame limit.

`evidence.compareScoped` takes `{repo,before,after,acrossContracts?,state?}` with each side `{runId,base,revision,runner,contractDigest}`. It validates both exact references and invokes the existing comparison in same-scope mode unless `acrossContracts:true` explicitly requests history mode. Different repository or runner is rejected even in history mode. Output is `{mode,status,before,after,scopeDifferences,environmentChanged,inputChanges?,claims,omissions}`. Claim and check identities, statuses and historical definition changes are projected from the comparison; raw paths, commands, logs and details are never returned. History metadata may report `unavailable`; scope differences explicitly identify base and contract digest changes. Recheck the record and manifest after comparison to reject concurrent replacement.

Regression surfaces: old validated schema 2 records and legacy bundles, skipped checks, qualification, provenance and artifact omissions, matching and mismatched pinned scopes, cross-contract history, bounded output, capabilities, unchanged existing clients. Verify with focused bridge/evidence tests, then repository verification gates; record unavailable worker and packaging gates in implementation evidence.
